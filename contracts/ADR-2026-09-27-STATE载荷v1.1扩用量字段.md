# ADR-2026-09-27：STATE(0x12) 载荷 v1.1 —— 新增 `reasoning` / `cacheRead` 用量字段

> 位置/命名依据：`contracts/README.md` §规则 + `StickS3_OpenCode_契约与演进设计补充.md` C10（最小字段）。
> 触发：用户 2026-09-26 裁定「`reasoning`/`cache` 要上屏」；本次（2026-09-27）用户确认继续 #3，采用四舍五入口径。

## 1. 问题
- `STATE(0x12)` 载荷 v1.0（`contracts/M4-STATE快照冻结.md`）仅含 `tokens.input/output/costMilli`。
- 真实 BR-03 快照另有 `usage.reasoning` 与 `usage.cacheRead`（实测 `771532` / `270690560`，见 `M4收口就绪核查.md` §4）**未上屏**；用户要求显示。
- 扩字段属「字段增删」→ 依 v1.0 §5 必须走 **ADR + 冻结新版本 + 黄金向量回归**。

## 2. 证据
- `plugin/src/core/state/types.ts:39-41`（`reasoning/cacheRead/cacheWrite: Availability<number>`）、`reduce.ts:85-87`、`stateRead.ts:95-97` → 快照**已提供**这三项。
- `host/src/bridge_snapshot.h` 现仅解析 `usage.input/output`；`firmware/.../s3p_state.h` 固定段 = 23B（v1.0）。
- MTU：设备首选 247（`ble_gatt.c` `PREFERRED_MTU`）；记录级 ATT 载荷 244B。

## 3. 候选
- **A（选定）**：扩**固定段**——在 `costMilli` 后追加 `reasoning u32`、`cacheRead u32`（各 4B），固定段 23→**31B**，`snapshotVersion` 1→**2**，TLV 起点随之后移。
- **B（未选）**：新增数值型 TLV（如 tag `0x04/0x05`）。→ 使 §2「变长文本区」语义变质，且需另立长度/端序规则，收益不抵复杂度。
- **C（未选）**：仅加 `reasoning`、弃 `cacheRead`。→ 不满足用户「reasoning/cache 上屏」。
- **`cacheWrite`（未选）**：本轮**不携带**（用户仅提 reason/cache；避免提前建设无关能力）。快照侧已有，后续如需再走一次变更。

## 4. 选定与语义
- 固定段新增两个 u32（LE），哨兵与 v1.0 一致：`0xFFFFFFFF`=unknown、`0xFFFFFFFE`=not_reported。
- `flags` bit5 `hasUsage` 语义**不变**（任一项 known 即置位）。
- 版本升 **2**：两端**同步升级**；v1 解码器遇 v2 依约**拒绝**（不误解析）。

## 5. 批准状态
- **用户已批准方向**（2026-09-26「reasoning/cache 要上屏」；2026-09-27「继续 #3」+「四舍五入」）。
- 本 ADR 记录该冻结；**契约文件同步升 v1.1**。

## 6. 关联 R · TC · M
- M：**M4**（收口执行清单 §6 #3）。约束 HLD §7.4 BR-03、C08。
- TC：`host/src/s3p_state_test.c`（黄金/边界，含新字段）；HIL 观屏。

## 7. 回退条件
- 若设备侧渲染/观测证明新字段无价值或占用不可接受 → 回退 v1.0（固定段 23、version 1），并回滚 `s3p_state.*` / `state_merge.*` / `bridge_snapshot.h` / `display.c` / `ble_gatt.c` 与黄金向量。

## 8. 验证状态
- 编码/解码单测（v2 黄金字节 + 往返 + 哨兵/边界）**通过**。
- host 构建 + 固件构建通过；刷机后串口 `cost/reason/cache` 与 USAGE 页**真机验证**（见证据）。
