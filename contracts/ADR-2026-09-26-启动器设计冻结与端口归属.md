# ADR-2026-09-26：启动器设计冻结与桥接端口归属修订

> 状态：**已批准（2026-09-26，用户逐条裁定 D1—D9）**。依据 [C10 可逆决策与冻结时间表](../StickS3_OpenCode_契约与演进设计补充.md)（ADR 最小字段见其 L144）、[contracts/README 规则](./README.md)、[S4.7 启动器 LLD 草案](../StickS3_OpenCode_S4.7-启动器LLD草案.md)。

## 1. 问题
host 侧缺"由谁、何时、以什么顺序**拉起并停止** `state_host`/`tray`"的定案；同时发现 `M1 桥接契约 §2` 的「端口由**启动器**分配」与现实现（插件取 `options.port ?? 0`，OS 随机）**不一致**，而该行属**已冻结**契约。

## 2. 证据
- `evidence/M4/2026-09-25-S4.2-生产host.md L4/L73`：用户裁定 host 形态＝**独立常驻可执行**；"Windows 服务/托盘包装**另议**"；`state_host.exe` **需手动或由启动器拉起**。
- `contracts/M1-桥接契约冻结.md L20`（已冻结）：`| 端口 | 启动器分配，不写死；… | HLD §7.1 |`。
- `plugin/src/bridge/server.ts L206`：`let boundPort = options.port ?? 0;`（OS 随机分配；实测 34901）。
- `StickS3_OpenCode_M4开发计划.md L32/L138`：S4.7「明确未交付」含"启动器/IPC"；"**启动器 LLD 待冻结**"。
- `StickS3_OpenCode_测试用例与追踪矩阵.md L147/L148/L154/L156/L158`：`SEC-06`/`UI-01`/`REL-01`/`REL-03`/`REL-05` 判据原文。
- `StickS3_OpenCode_功能模块HLD.md §11.3 L431`：M08 启动握手「仍需 M1 验证」（故 B 不宜现在做）。

## 4. 选定（D1—D9，用户 2026-09-26 逐条裁定）
| # | 决策 | 选定 |
| --- | --- | --- |
| **D1** | 启动器范围 | **A**：仅 Windows 侧拉起器 |
| **D2** | 进程模型 | **a**：常驻 `launcher.exe` 监督（拉起/存活检测/崩溃重启/退出收尾） |
| **D3** | 自启 | **a**：不自启（手动运行） |

| **D6** | 配置发现 | **a**：`STICKS3_BRIDGE_JSON` 优先；否则遍历候选且**发行版名可配置**（不再硬编码 `Ubuntu`） |

## 5. 未选定（明确排除）
- **SCM 服务化**：与 `REL-01`「不修改全局安全策略」、`UI-01`「不需要常驻管理员」冲突，且 `evidence L4` 已列"Windows 服务"为**另议**。
- 一次性引导（D2-b）、`tray` 内嵌持有（D2-c）。
- 一切自启机制（Run 键/任务计划/启动文件夹/服务）——D3-a 选定即排除。
- 设备侧（固件）任何改动；M6 安装器/发布布局。
