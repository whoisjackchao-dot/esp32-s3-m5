## 2. 计时方案 B（起点/终点/误差）

**两个时刻都在主机时钟上（Windows `QueryPerformanceCounter`/单调毫秒），无跨端时钟换算。**

| 位置 | 定义 | 依据 |
| --- | --- | --- |
| **起点 t0** | 主机收到设备**串口**会话结束行的时刻：提前结束场景取 `button: BtnA 松开`；30s 硬停场景取 `END recID=`（无松键事件） | 方案B：外部观察设备侧"松键/硬停"事件 |
| **终点 t1** | 主机收到 **BR-04 `POST /v1/draft/append` 响应且 `status=applied`** 的时刻 | M1 契约 §4：线性化点=插件内同步更新 Prompt；`applied`="set+readback 成功并记录" |
| **点估计** | `latency = t1 − t0`（秒） | — |
| **误差 Δ** | 串口单向延迟估计：同一会话的 **BLE END 通知到达时刻** 与 **串口 END 行到达时刻** 之差（两者设备发射时刻相同）→ `Δ = t_serial − t_ble`，取 N 次中位数 | 报告误差，不隐藏 |
| **误差 Δ₂（打戳抖动）** | 串口按块读取：同一块内的多行共享一个到达时刻，故锚点行时刻可能比真实到达略晚（设备日志稀疏，实测有界为块内相邻行间隔，通常 ≪100ms）。作为**二阶项**随 Δ 一并报告 | 诚实标注测量受限，不假装零误差 |

**判定用点估计，但须报告 Δ；若 `latency ≤ 5s` 判达标，`latency − Δ > 5s` 判不达标，灰区（`5s−Δ < latency ≤ 5s`）标"需人工复核"，不自动放行。**

## 3. 前置条件（每次测量前核对并记录）

1. 设备已连接、会话已绑定（`/v1/binding` `canAppend=true`）。
2. 固件为本增量版（`END.totalFrames` 反映实际时长；见 `evidence/M3/2026-09-23-松键提前结束HIL.md`）。
3. 触发方式 = **物理按键**（`tools/button_hil.py` 路径，**不发 READY**）；起点是松键而非 READY。
4. 网络/蓝牙环境按 Q05 记录：工位约 0.3～2 米、无墙体遮挡、无线共存条件、嘴到麦克风距离。
5. 真实云调用（智谱 ASR，**计费**）——须**独立授权与费用上限**（见 §6 待决）。

## 8. 变更记录

### v1.1（2026-09-23）

1. **分组时长修订（用户 2026-09-23 指示）**：中间组 **15s → 10s**；组数仍 3（**5s / 10s / 30s**）。
2. **次数修订（用户 2026-09-23，两次）**：先 30s 组 **20 → 5**（因"须持满 30s"工作量）；再 **5s、10s 亦 20 → 5**（理由："之前跑过、可信度高"）。**最终各组均为 5 次**。
3. **门槛**：由已批准 19/20（95%）推导，`ceil(0.95×5)=5/5`（**零容忍**，任何 1 次超时即该组不达标）。原批准的 5/15/30 中 15s 组作废。

> **⚠ 边界登记（重要，不得省略）**：缩减理由中的"之前跑过、可信度高"**不构成证据**——2026-09-23 战役 46 次**未记录任何时延**（`t1` 缺陷，`latency_s` 全空），其可证明的仅为"端到端跑通"（42/46 `applied`、46/46 摘要 MATCH），**不能**证明"≤5s"。故本测量为**缩减样本版**：n=5 且零容忍**无法**体现原 Q03"约 5% 失败率"的统计效力。**结论不得按原 Q03 口径宣称达标**；如需该口径，须补足样本或另行批准。
2. **录音时长必须真达到对应时长（用户裁定"严格"）**：录制时长（`end_samples/16000`）必须落在该组目标窗内，否则该次**无效、须重做**（不计为合格）。具体窗口取值**待用户确认**（见 §9）。
3. **实测缺陷登记（严重）**：2026-09-23 战役 46 次运行**全部 `latency_s=null`**——`voice_append.exe` 的 `[3] 桥接 HTTP …` 行含中文，子进程 stdout 被 Python 以 **cp1252** 解码成乱码，`startswith("[3] 桥接 HTTP")` 永不命中 → `t1=None`。草稿追加成功（applied 42/46、摘要 46/46 MATCH）但**时延从未测得**；该 46 次记录**不可用于验收**。
   - 修复：子进程 `encoding="utf-8"` + t1 判定改用 ASCII 前缀 `[3]`；抽 `classify_append_line()` 并加回归测试（`tools/test_q03_run.py`）。
   - 同时发现：**实际录音时长与组名不符**（"15s"组实际 9.78–13.38s；"30s"组 5 次中 3 次为 0.24/0.42/5.22s，无一达 30s）→ 印证第 2 条的必要性。
4. **健壮性**：campaign 每次运行前重载 `bridge_env.ps1`，应对 OpenCode 重启 / `tuiEpoch` 旋转（2026-09-23 17:28 实测因 OpenCode 退出致旧 URL 失效、后续 `no_response`）；桥接装载失败即停并提示续跑。
5. **证据留存**：每次运行保存 `serial_<组>_<次>.log`（锚点行 + 到达时刻），此前仅存内存，致事后无法复核。
