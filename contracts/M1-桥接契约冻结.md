## 2. 传输与安全边界

| 项 | 冻结值 | 依据 |
| --- | --- | --- |
| 监听地址 | `127.0.0.1`，**禁止** `0.0.0.0` | SEC-01 |
| 端口 | **由桥接侧分配（OS 随机：`options.port ?? 0`）并经 `bridge.json` 发布**，launcher/托盘只读发现；不写死；不作为 OpenCode 服务端口〔v1.1 修订，见 ADR-2026-09-26〕 | HLD §7.1 / ADR-2026-09-26 |

| token 交接 | M1 允许：`0600` 权限文件或子进程环境变量；**禁止**进命令行、普通日志、git | IPC-02 |
| 请求媒体类型 | 仅 `application/json`，否则 `415` | C02 |

| `Host` 头 | 必须为 `127.0.0.1:<port>` 或 `localhost:<port>`，否则 `403` | SEC-01 |
| CORS | 不返回任何 CORS 头 | SEC-01 |
| 请求体上限 | `BODY_MAX_BYTES = 8192` | C02 |
| 正文上限 | `TEXT_MAX_LEN = 4096` 字符 | C02 |

## 3. 端点与状态码

| ID | 方法 / 路径 | 成功 | 失败 |
| --- | --- | --- | --- |
| BR-01 | `GET /v1/health` | `200` `{protocolVersion, pluginVersion, tuiEpoch, alive}` | `401` |
| BR-02 | `GET /v1/binding` | `200` `{tuiEpoch, sessionID, routeMatches, bindingRevision, canAppend, blockReason}` | `401` |
| BR-03 | `GET /v1/state/stream` | `200` SSE（M1 最小实现；完整字段 M4） | `401` |
| BR-04 | `POST /v1/draft/append` | `200` `status=applied` | `202`/`409`/`429`/`400`/`401`/`415` |
| BR-05 | `GET /v1/operations/{operationID}` | `200` `{status, reason?}` | `404` unknown；`401` |
| BR-06 | `POST /v1/operations/{operationID}/cancel` | `200` `{status: cancelled\|already_applied}` | `409` identity_error；`401` |

BR-04 响应体（成功）：

```json
{
  "protocolVersion": 1,
  "tuiEpoch": "example-epoch",
  "operationID": "example-operation",
  "status": "applied",
  "reason": null
}
```

### 3.1 状态 → HTTP 映射（全接口统一）

| status | HTTP | 含义 | 客户端允许动作 |
| --- | --- | --- | --- |
| `applied` | 200 | 已校验并完成写入 | 按终态处理，不重复 set |
| `processing` | 202 | 已接收未终态 | 查询/取消，不并发重投 |
| `rejected` | 409 | 写入前明确拒绝，attempt 结束 | 原 payload 可安全重试（仍以 operationID 去重） |
| `conflict` | 409 | 同 operationID 不同正文/目标 | 新 operationID；不覆盖首份回执 |
| `stale_epoch` | 409 | epoch 已过期 | 重新绑定 |
| `target_mismatch` | 409 | 目标会话/route 不符 | 恢复目标后「重试填入」 |
| `cancelled` | 200 | 已处理撤销且未 commit | 禁止同 ID 再写入 |
| `already_applied` | 200 | commit 已先发生 | 不撤销草稿 |
| `uncertain` | 200 | set 可能已发生，终态未知 | **人工检查**；禁止自动重放/回滚 |
| `unknown` | 404 | 当前无记录，**不代表未在途** | 查询/取消并建墓碑，不直接重发 |
| capacity 满 | 429 | 回执容量耗尽 | 查询/取消仍可用；不接受新 operation |
| 认证失败 | 401 | token 缺失/错误 | 不重试，检查凭据 |
| 载荷非法 | 400 | schema/字段错误 | 修正后重试 |

**规则：客户端必须以 `status` 字段判定结果。除 `applied`（及幂等 `already_applied`）外一律不得当作成功；`uncertain` 必须人工处理。禁止把所有业务失败包装成 200 后忽略 `result`。**

## 4. operation 状态机与线性化点

```
              ┌─────────────┐
   append ───►│ processing  │──► applied      （set+readback 成功并记录）
              │             │──► rejected     （写入前拒绝）
              │             │──► cancelled    （墓碑先到，未 commit）
              │             │──► uncertain    （set 后 readback/记录失败）
              └─────────────┘
```

- **线性化点**：插件内**同步**更新 Prompt 并记录结果的那一步；不是松键、不是 HTTP 返回时间（C03）。
- 取消先到 → 保存墓碑；同 epoch 同 operationID 的迟到 append **必须**被墓碑拒绝（TX-10）。
- commit 先到 → cancel 返回 `already_applied`，不自动删除草稿（TX-11）。
- 取消/到期无法到达 TUI 且写入可能在途 → `uncertain`，不承诺远端未写入（TX-12）。
- 同 epoch 同 operationID 不同正文或目标 → `conflict`；不把首份成功回执复用给第二份（TUI-10）。
- 指纹 = `hash(target_session + route + text)`，不落日志（C02）。

## 4.1 绑定/路由校验的实现约束（2026-09-20 核实）

依据 `@opencode-ai/plugin@1.18.31` 的 `dist/tui.d.ts`：

| 事实 | 影响 |
| --- | --- |
| `TuiRouteCurrent` 是判别联合：`{name:"home"}` \| `{name:"session";params:{sessionID;prompt?}}` \| `{name:string;params?:Record<string,unknown>}` | 当前会话 ID 只在 `name==="session"` 的 `params.sessionID` |
| 存在 `{name:string}` **兜底成员**，TypeScript **无法**收窄 `route.name==="session"` | 路由校验必须做**运行时类型检查**（`typeof id === "string"`），不能依赖编译期收窄 |
| `TuiPromptRef` = `{focused, current, set, reset, blur, focus, submit}` | `current`/`set` 可用；**`submit()` 存在但本项目禁止调用**（TUI-17 需实际传输记录证明未调用） |
| `TuiPromptInfo` = `{input: string, mode?: "normal"\|"shell", parts: [...]}` | 追加须保留 `parts`（附件 extmarks），`set` 是整体替换 |

> 本表修正了可行性核查原表述「TuiRouteCurrent 包含 sessionID」的不精确之处（该文档已同步修订）。

## 5. 容量与期限（已批准值，2026-09-20）

| 符号 | 批准值 | 单位 | 说明 |
| --- | --- | --- | --- |
| `RECEIPT_CAPACITY` | 64 | 条 | 满则 `429` 拒绝新 operation；**不静默淘汰已完成回执**；查询/取消仍可用（TUI-15） |
| `APPEND_DEADLINE` | 10 | 秒 | 主机等待 BR-04 回执上限（起点=请求发出） |
| `RECEIPT_TTL` | 300 | 秒 | 回执/墓碑在 epoch 内保留上限；epoch 旋转即全部失效 |
| `TEXT_MAX_LEN` | 4096 | 字符 | 单次追加正文上限 |
| `BODY_MAX_BYTES` | 8192 | 字节 | 请求体上限 |

> `APPEND_DEADLINE` 与 C10 表中「尾帧/追加回执超时」相关但不等同：尾帧超时属 BLE 线协议（M2 前冻结）。此处只冻结 BR-04 的主机侧等待上限。

## 6. 明确不做（M1 安全边界）

- 不提供 submit / 审批 / shell / 任意文件 / abort / 清空草稿接口（SEC-02、TUI-17）。
- 不自动重试、不自动切换会话、不自动清理已写草稿。
- 不使用 `/tui/append-prompt` 作为生产安全追加路径（E03/E07 已证其无目标保护）。
- 不把 `POST /session/{id}/message`、`/tui/submit-prompt`、`prompt_async` 暴露给桥接。
