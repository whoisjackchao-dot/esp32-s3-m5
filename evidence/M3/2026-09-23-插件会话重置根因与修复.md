# 插件会话重置：根因与修复（2026-09-23）

> 用例：TUI-16（replace 模式原生行为回归）｜需求：R11｜节点：M1（安全草稿通道交付物）
> 阻塞关系：本缺陷阻塞 M3 故事4 用户价值闭环（重启即复发）
> 类型：T（槽位转发单测）＋ H（真实 TUI 行为，未验证）
> 证据分级：**根因**＝上游二进制级（opencode 1.18.32）＋ 类型定义；**修复**＝本次实测；
> **真实渲染行为**＝未验证（见 §6）。

## 1. 故障现象（用户报告，2026-09-23）

- 每次输入对话都导致会话重启（"每次输入对话导致会话重启"）
- opencode 界面还在，但变成**空会话**，无报错文字
- 正常对话过程中直接**丢失上下文、开启新会话**
- 中断前给项目植入了一个插件（ESP32-S3M5 的 TUI 桥接插件）

## 2. 根因（二进制级证据）

宿主渲染 `session_prompt` 槽位时传入 `session_id`/`on_submit`/`visible`/`disabled`/`ref`；
渲染 `home_prompt` 槽位时**不传** `sessionID`/`onSubmit`。两者复用**同一个**
`api.ui.Prompt` 组件。

插件（`plugin/src/index.ts`）以 replace 模式替换 `session_prompt` 槽位后，
**一个宿主 props 都没转发**（首版只写 `api.ui.Prompt({ ref })`）→ 会话内输入框退化为
"首页新建会话"输入框 → **每次回车都在新建会话并跳转** → 空会话 + 上下文丢失；
旧会话正在跑的请求被跳转取消 → `MessageAbortedError`。

| 证据 | 内容 | 来源 |
| --- | --- | --- |
| 上游运行时 | `Slot({name:"session_prompt", mode:"replace", session_id, visible, disabled, on_submit, ref, children: Prompt({sessionID, onSubmit:()=>jf(), ...})})` | opencode 1.18.32 二进制 `strings` 提取（2026-09-23 会话 `ses_f333d5c77`） |
| 上游运行时 | `home_prompt` 的 `Prompt({ref, right, placeholders})` 无 `sessionID`/`onSubmit` | 同上 |
| 类型 | `TuiHostSlotMap.session_prompt: {session_id; visible?; disabled?; on_submit?; ref?}` | `@opencode-ai/plugin/dist/tui.d.ts` |
| 类型 | `TuiPromptProps: {sessionID?; visible?; disabled?; onSubmit?; ref?; ...}` | 同上 |
| 时间线 | 插件 11:17 首次加载 → 11:18:06 起重启风暴（14 顶层会话几乎"一输入一建"） | `plugin-meta.json` + `opencode.db` |

> 责任认定：2026-09-21 spike 的 `FINDINGS §1.6` 曾错误断言"槽位 props 仅 {theme}"，
> 首版配方据此只传 ref。**该结论已被二进制证据证伪**，`spike/FINDINGS.md` 已修订
> （§1.6/§3 更正、§5 新增）。

## 3. 修复（方案 B：转发宿主 props）

新增 `plugin/src/plugin/slotPrompt.ts`：

```ts
export function buildSessionPromptSlot(
    render: (props: TuiPromptProps) => unknown,
    capture: (sessionID: string, ref: TuiPromptRef | undefined) => void,
) {
    return (rawProps: unknown) => {
        const props = (rawProps ?? {}) as SessionPromptSlotProps;
        const sessionID = props.session_id;
        return render({
            sessionID, visible: props.visible, disabled: props.disabled,
            onSubmit: props.on_submit,
            ref: (ref) => { props.ref?.(ref); if (sessionID) capture(sessionID, ref); },
        });
    };
}
```

`plugin/src/index.ts` 接入（替换首版内联实现）：

```ts
session_prompt: buildSessionPromptSlot(
    (props) => api.ui.Prompt(props),
    (sessionID, ref) => refs.capture(sessionID, ref),
),
```

转发全部宿主 props（保持 opencode 原生输入框契约）＋ ref 回调捕获引用（桥接追加草稿功能不丢）。

## 9. 二次修复（2026-09-23，方案 B 参数位置更正）

> 本节登记：首版方案 B（§3）**真实 TUI 无效**；二次修复改变 renderer 签名。
> 用例：TUI-16｜需求：R11｜类型：T（单测，先 RED 后 GREEN）＋ H（真实 TUI 行为，仍待确认）。

### 9.1 首版无效原因

用户 14:14/14:16 重启后仍"一输入一建会话"。二次根因：**首版把 renderer 第 1 参当宿主 props**。
opencode solid Slot 组件（1.18.32 二进制级）以 **`renderer(context, data)`** 双参调用插件：
第 1 参 context 仅 `{theme}`，第 2 参才是 splitProps rest（`session_id/on_submit/visible/disabled/ref`）。
首版单参签名读到的恒为 `{theme}` → `session_id` 恒 undefined → 退化依旧。

### 9.2 二进制证据（2026-09-23 15:3x 会话独立复核）

从 `/home/shiwenc/.opencode/bin/opencode`（1.18.32）`grep -a` 提取：

```js
// Slot 组件本体：剥离控制属性，rest $ = 宿主 props
function D9(_){ let [J,$]=_8(_,["registry","name","mode","children","pluginFailurePlaceholder"]) ...
// 渲染 entry：renderer 以 (context, rest) 两参调用
F=(D,M)=>{ ... I=D.renderer(Z().context,$) ... }
// replace 模式：仅渲染插件 renderer 输出，原生 children 被替换
if(M==="replace"){ let I=D.map((S)=>F(S)) ...
// registry 包装层同样按两参转发
renderer:(Q,q)=>Z(Q,q)
```

宿主对 session_prompt 的传参（同轮提取）：
`Slot({name:"session_prompt",mode:"replace",session_id,visible,disabled,on_submit,ref,children:Prompt(...)})`。
