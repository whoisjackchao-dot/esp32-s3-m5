# ES8311 无响应诊断记录（M2）

> 2026-09-22。本记录只把**本次实测**当事实；推断与待验证假设单列，不冒充结论。
> 关联：`contracts/M2-BLE线协议冻结.md`、`M5StickS3_硬件知识文档.md`、`firmware/sticks3/main/pm1.h`。

## 1. 背景

M2 阻塞项。提交 `2713fc9` 记录：「A3a/b 故障注入演示脚本就绪，待 ES8311 硬件恢复后执行（当前编码器双地址 NACK）」。

本次实测确认：**ES8311 在 I2C 上完全无应答**，设备侧音频采集通路无法初始化（心跳 `audio_ready=0`），A3a/A3b/30 秒录音演示均因此无法执行。

## 3. 已确证事实（本次实测）

**F1 — I²C 总线本身健康**：全总线扫描（0x03–0x77）稳定命中 `0x68`(BMI270) 与 `0x6E`(M5PM1)。
```
I (7545) audio_capture: i2c scan ack: 0x68
I (7545) audio_capture: i2c scan ack: 0x6e
```

**F2 — ES8311（0x18/0x19）全程无应答**：连续 5 轮重试（约 14 秒）均 NACK。
```
E (7555) audio_capture: 总线上无 ES8311 应答（0x18/0x19 均 NACK）
E (7755) audio_capture: es8311 初始化失败（双地址重试后仍无应答）
```

**F3 — PM1 可达、主要电源轨已开**：`device_id=0x50`；`PWR_CFG=0x17`（chg=1 dcdc=1 ldo=1 boost=0）。

**F4 — 提前使能 L3B（PM1 GPIO2）不能恢复应答**：将 `pm1_l3b_lcd(true)` 提到探测之前（固件 SHA `929210f9…`）后重测，仍 NACK。

**F5 — 正常启动只能靠物理断电重启**：USB-JTAG 的 RTS 复位使芯片进入 `boot:0x3 DOWNLOAD`，app 不运行；**双击关机 → 单击开机**后 app 正常运行。这是此前「串口完全无日志」的真因，非固件缺陷。

**F6 — app 其余子系统正常**：`s3p_proto selftest PASS`、opus 会话层就绪、BLE GATT 启动、`display init OK`（背光开）。

## 4. 待验证假设（非事实）

- **H1（主要）**：PM1 GPIO 输出未配置。固件只写 `GPIO_OUT(0x11)`，从未写 `GPIO_MODE(0x10)`；若引脚未设为输出，GPIO2/GPIO3 不驱动，则 L3B 与 codec 使能均无效 —— 也能解释「屏幕空白」。
- **H2**：ES8311 由 PM1 的其它寄存器/LDO 供电，而非 GPIO2/GPIO3。
- **H3**：ES8311 器件本身失效（硬件故障）。
- **H4**：I²C 层面针对 0x18 的特殊问题（地址冲突/时钟拉伸/上下拉）。

## 8. 根因裁定与修复验证（2026-09-22 完成）

### 8.1 根因（已确证）

权威依据：M5GFX `M5GFX.cpp` 与 M5Unified `M5Unified.inl`（`board_M5StickS3`）源码，及 M5Stack 官方文档。

**M5PM1 的 GPIO 必须经 4 个寄存器配置后才能驱动**，M5GFX/M5Unified 的实际序列为：
```
0x16 清位 → GPIO 功能
0x10 置位 → 输出模式
0x13 清位 → 推挽
0x11 置位 → 输出电平
```

原固件只写 `0x11`，**从未配置 `0x16/0x10/0x13`** → PM1 GPIO2 始终未真正驱动 → **L3B 供电轨从未上电**。官方文档明确 L3B（PYG2_L3B_EN）为「LCD 背光、MIC、SPK」供电，ES8311 即在其上。这同时解释了 **ES8311 NACK** 与 **屏幕空白** 两个症状。

### 8.2 修复

- `pm1.c`：新增 `pm1_gpio_output()`，按 0x16→0x10→0x13→0x11 顺序配置引脚；`pm1_es8311()`/`pm1_l3b_lcd()` 改走该路径。
- `audio_capture.c`：探测前使能 L3B（`pm1_l3b_lcd(true)`），确保编解码器先上电。

### 8.3 验证（修复后实测启动日志）

```
I (996)  audio_capture: i2c scan ack: 0x18          ← ES8311 恢复应答
I (1036) ES8311: ES8311 in Slave mode and I2S format
I (1036) audio_capture: es8311 ready @0x18
I (1046) audio_capture: i2s rx running (MCLK18 BCLK17 WS15 DIN16)
I (1526) sticks3: audio 1s: samples=15360 min=-2819 max=3183 avg=0
```
心跳 `audio_ready=1`（修复前恒为 0）；采到**非零真实音频样本**，麦克风通路打通。首次探测即成功，无重试。

### 8.4 跨文档冲突裁定（对应 §5）

以**官方 PinMap + M5GFX/M5Unified 源码**为准：
- **PM1 GPIO2 = L3B 供电轨**（LCD/MIC/SPK；ES8311 所在）✅
- **PM1 GPIO3 = SPK 功放使能**（`PYG3_SPK_Pulse`）✅
- `pm1.h` 原「ES8311 使能 = PM1 GPIO3」为**误记，已修订**（`pm1.h` 头注释同步更正）。
- 另一条原注释「不复刻该序列会在 PM1 状态复位后失去编码器」在因果上不成立——真因是 GPIO 未配置，非看门狗序列；已随注释更新。

### 8.5 附带确认

`display_init` 在修复后于 t=3596ms 完成（修复前 t=15306ms），因不再有 5 轮 codec 重试等待。屏幕是否有内容仍需用户目视确认（L3B 已上电，理论上应恢复显示）。
