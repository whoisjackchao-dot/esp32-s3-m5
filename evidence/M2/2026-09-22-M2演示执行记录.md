## 3. A3b 断线重连演示 —— ❌ FAIL（真实缺陷）

**命令**：`tools/ble_reconnect_test.py`

**主机侧输出（修复前）**：
```
[PASS] scan found ...
[PASS] session started, frames_received=28
disconnected mid-session at frame ≈28
[PASS] reconnect in 0.19s (limit 15.0s, no re-pairing)
[FAIL] replay detected: 2 stale session packets (Q05 禁止重放)
```

**修复后重测**（固件 SHA `b0ad5538…`，新增断线中止钩子）：
```
[PASS] reconnect in 0.16s (limit 15.0s, no re-pairing)
[FAIL] replay detected: 2 stale session packets
```

**结论**：**仍失败**。断线后旧会话残余帧仍经新链路送达，违反 Q05「自动重连只恢复已绑定链路，不重放语音事务」。

**已实施但无效的修复**：`audio_session_abort()` + `ble_gatt_set_disconnect_cb()`，在 BLE 断线事件中置中止标志，`run_session()` 每帧检查后提前返回。

**未定位的疑点**（供后续）：
- 主机 0.16s 即重连并重新订阅，早于中止生效/帧边界检查；
- 2 个残余包可能来自 NimBLE 通知队列在重连后的投递，而非会话循环继续；
- 需在设备侧抓断线→重连窗口日志，确认 `会话中止` 是否打印及其时序。

**当前判定**：A3b 为 M2 未通过项，阻塞 M2 出口（出口判据要求"所有本节点关键失败路径被观察"且无未决缺陷）。

## 4. 环境事实（本次实测，供复现）

## 6. A3b 复判：失败为**测试假象**（2026-09-22 设备侧证据推翻前判）

前判「A3b FAIL：重放 2/4 个旧会话包」经设备侧日志复核**不成立**。设备侧完整时间线：

```
I (268972) ble_gatt: connected, conn=1（等待主机发起 Just Works 配对）
I (269212) ble_gatt: enc change conn=1 status=0
I (269212) ble_gatt: audio notify ON
I (269332) ble_gatt: MTU exchange: 247 (conn=1)
I (269572) ble_gatt: host READY: protoVer=1 mtu=247
I (269572) audio_session: BEGIN recID=2 frames=500 16kHz/60ms mtu=247
I (288052) audio_session: END recID=2 frames=500 samples=480000 opus=66058B (132B/帧) summary=0x1555856e 耗时=18483ms
I (294232) ble_gatt: disconnected reason=0x213; 重新广播
```

**判据**：
- 整段测试期设备侧**只有 1 次 `connected`、0 次中途 `disconnected`**；
- 会话**跑满 500 帧**（18.48s）才正常 `END`，**从未被中止**；
- 唯一一次 `disconnected` 发生在会话结束（288052）之后（294232）。

**结论**：`bleak` 的 `BleakClient` 上下文退出（`close()`）在 Windows 上**未真正断开链路**——OS 复用同一 ACL 连接，测试的"reconnect"在链路层为空操作。phase-3 收到的 4 个包是**同一条合法运行中会话**的帧，被脚本误计为"stale session packets"。

**因此**：
- ❌ 原「A3b FAIL / Q05 违反」判定**撤销**；
- ⚠️ 但 Q05「重连不重放语音事务」**仍未获有效验证**——现有测试方法在 Windows 上无法制造设备可观测的真实断链，故该属性为 **UNVALIDATED（未验证）**，非 PASS 亦非 FAIL；
- 已加的 `audio_session_abort` + `ble_gatt_set_disconnect_cb`（固件 SHA `b0ad5538…`）为**正确的防御性实现**，但在本测试中未被触发（无真实断链），**不能据此声称已验证**。

**修正测试方法的候选**（未实施）：
1. 制造设备可观测的真实断链：Windows 蓝牙适配器禁用/启用、设备移出范围、或由设备侧主动断开；
2. 或在测试中用能真正触发 LL terminate 的方式（而非 `BleakClient.close()`）；
3. 断言应区分「同一会话的连续帧」与「新链路上重放的旧会话帧」（例如按 recordingID 与连接实例共同判定）。

## 7. Q05「重连不重放」—— ✅ VERIFIED PASS（2026-09-22，真实断链）

**修正方法**：原测试用 `BleakClient.close()` 制造断链，Windows 缓存 ACL 导致设备侧零断线（见 §6）。本版改为**设备主动 terminate**（测试专用控制消息 `0x7F`），断链对设备必然可观测。

**命令**：`tools/ble_q05_reconnect_test.py`

**主机侧**：
```
[PASS] session started, frames_received=25
[PASS] device-initiated drop; c1.is_connected=False
[PASS] reconnect in 0.27s
[PASS] no replay after real reconnect (0 stale packets in 3.0s)
[PASS] new session healthy after reconnect
--- Q05 reconnect demo PASS ---
```

**设备侧证据链**：
```
I (23859) audio_session: BEGIN recID=1 frames=500 16kHz/60ms mtu=247
W (24999) ble_gatt: 测试钩子：主动断开 conn=1
I (25069) ble_gatt: audio notify off
I (25069) ble_gatt: disconnected reason=0x216; 重新广播      ← 真实断链（设备可观测）
E (25079) audio_session: 通知失败 1 次，会话取消            ← 在途会话被正确终止
I (25419) ble_gatt: connected, conn=1                        ← 重连（不重新配对）
I (25669) ble_gatt: audio notify ON
I (25789) ble_gatt: MTU exchange: 247 (conn=1)
（静默 3.0s → 0 个会话包）
I (31419) ble_gatt: host READY: protoVer=1 mtu=247
I (31419) audio_session: BEGIN recID=2 frames=500            ← 新会话健康
```

**判定**：Q05「自动重连只恢复已绑定链路，不重放语音事务」**在真实断链下验证通过**。会话在断线时终止（`通知失败→会话取消`），重连后无任何旧会话帧投递。

**注意事项（交付前必读）**：
- 本次验证固件 SHA `9d1cde757bd78eb68f934a915c6d975a51e8d3cc9107010f53a79b87afac25f7` **含测试专用钩子**（控制消息 `0x7F` → `ble_gap_terminate`）。该消息不在冻结契约内、保留值；**交付固件应移除此钩子或明确登记为已接受的测试脚手架**，否则"交付固件 = 已验证固件"的对应关系不成立。
- 会话终止实际由 `notify 失败→会话取消` 路径完成；`audio_session_abort()` 钩子为同向防御，本次未被单独观测。
