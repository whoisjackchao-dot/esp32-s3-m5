# 证据：S4.5 电量读数（M5PM1 reg0x22 mV + 充电位）——三页常驻 BAT

> 日期：2026-09-26。范围：补齐 S4.5「电量读数待查」项——定位硬件通路、实现读取、三页常驻显示、真机验证。
> 用户裁定：电量在**三页常驻**显示；`BAT` 16px 蓝、百分比/充电 8px 白。
> 本文件是证据记录。

## 1. 通路（调研结论）

| 项 | 结论 | 来源 |
| --- | --- | --- |
| 电池电压 | **M5PM1**（I2C 地址 `0x6E`）寄存器 **`0x22` = VBAT_L**，**2 字节小端，值即毫伏** | M5Unified `M5PM1_Class` / PM1 寄存器表 |
| 充电状态 | **`0x12` bit0**（低 = 充电中）；需将 **PM1 GPIO0** 配为 GPIO 输入 | 同上 |
| 百分比 | `pct = clamp((mv - 3300) * 100 / 800, 0, 100)` | M5Unified 公式 |

> 硬件文档原仅记「M5PM1 GPIO0=充电状态、未见电池 ADC 通路」。本次查明：**电池电压走 PM1 寄存器，而非 ESP32 ADC**（M5StickS3 无电池 ADC 引脚）。

## 2. 交付物（代码）

| 件 | 类型 | 说明 |
| --- | --- | --- |
| `firmware/sticks3/main/pm1.c` / `pm1.h` | 驱动 | 新增 `pm1_battery(uint16_t *mv, int *pct, bool *charging)`；PM1 GPIO0 配 GPIO 输入 |
| `firmware/sticks3/main/display.c` / `display.h` | UI | `display_set_battery()`；**公共区**绘制 `BAT n%`（三页常驻） |
| `firmware/sticks3/main/main.c` | 调度 | `power_task` 每 **10s** 读电量 → `display_set_battery()`（脏标记重绘） |

## 3. 真机 HIL（COM5）

复位后串口捕获（`tools/device_log.py COM5`）：

```
I (16238) sticks3: battery 4200mV 100% chg=0
I (16238) sticks3: hb: uptime=15s heap=8439824 audio_ready=1 ble_conn=0
```

- 读数 **4200 mV → 100%**（USB 供电满电），`chg=0`（未充电）——与插电满电态一致。
- 显示侧：`BAT 100%` 于**三页**底部常驻；`BAT` 16px 蓝、值 8px 白。

## 5. 效力边界（不得省略）

- **未验**：放电过程中百分比随电压下降（需脱离 USB 观察）；**`CHG` 充电态的真机显示**（本次 `chg=0`）。
- **未做**：**USB 插入/拔出策略（UI-04）**——本项只交付「可读并可显示电量」。
- 百分比为**线性近似**（3.3–4.1V），未做电压-SOC 实测标定；锂电池平台期会使中段读数偏乐观。
- 采样为**单点**读数，无滤波/均值；`chg` 位极性依 M5Unified（低=充电），未在放电↔充电切换下实测。
