## 5. 效力边界（不得省略）
- **未验**：崩溃重启（Slice 2，**未实现**）；日志**轮转**路径（本次日志远小于 1 MiB，**未触发**）；真实设备 E2E（`E2E-01` 全链路不在 Slice 1）；多用户/多会话。
- **测试工具伪影（非产品缺陷）**：PowerShell `Start-Process -RedirectStandardOutput` 下 `ExitCode` 读数为空；退出码由 `launcher_2.txt` 的 `already running - exiting` + 源码 `return 2` 佐证。
- 修复 2 处**格式化缺陷**（宽串用 `%s`、窄串用 `%ls` → 诊断行空白）：`descriptor …`、`rotate: …`。
- 一次**测试方法失误**：曾把第二实例以 `| Out-String` 前台管道运行 → 命令挂起（**非产品缺陷**，已改为 `WaitForExit(10000)` 有界等待并清理进程）。
- 启动器**不安装、不自启**，仅手动运行（D3=a）。
- **句柄继承已收紧（修复）**：原实现用 `CreateProcessW(..., bInheritHandles=TRUE, ...)` 会把 launcher **从父进程继承来的全部可继承句柄**（含调用方的 stdout 管道）一并传给 `state_host`/`tray`。已改为 `STARTUPINFOEXW` + `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` **只放行子进程日志句柄**（`EXTENDED_STARTUPINFO_PRESENT`，失败则回退旧路径）。这解释了本次"命令挂起"现象：派生的常驻进程持有调用方管道 → 调用方等不到 EOF。**验证**：改后重建（184,832 B）并复跑有界冒烟，四项判据全部仍通过。

## 6. Slice 2：崩溃重启 + 指数退避 + 轮转触发（同日完成并验证）

实现（**仍只改 `launcher.cpp`**）：
- 子进程退出→按**指数退避**重启：`delay = min(1000ms << (restarts-1), 30_000ms)`；**退出前存活 ≥60s 则重置**退避计数（避免长稳定后仍被重罚）；重启**复用同一日志文件**（防日志爆炸）。
- 轮转（D7）在**启动时**评估（子进程输出由我们直接重定向到文件句柄，运行中无法按尺寸切分）。

验证（`C:\Temp\launcher_smoke2.ps1`，有界）：
```
pre_log_size=1258291
P1 alive=True
before_kill=336
after_kill=3204
restarted=True
rotated=True
cleanup ok
--- launcher_1.txt ---
[launcher] rotate: state_host over 1258291 bytes -> state_host.1.log
[launcher] started state_host pid=336 -> ...\state_host-20260926-235952.log
[launcher] descriptor ready after 250ms
[launcher] started tray pid=16260 -> ...\tray-20260926-235952.log
[launcher] child exited: state_host code=4294967295 (alive=5906ms) -> restart #1 in 1000ms
[launcher] started state_host pid=3204 -> ...\state_host-20260926-235952.log
```

| 判据 | 结果 |
| --- | --- |
| **崩溃重启** | ✅ 杀 `state_host`(336) → 自动重启为 **3204**；日志 `restart #1 in 1000ms`（退避基数 1 s 正确） |
| **日志轮转（此前未验）** | ✅ 预置 1,258,291 B 旧日志 → `rotate: … -> state_host.1.log`；`rotated=True`，`state_host.1.log` 大小 = 原值 |
| 重启不产生日志爆炸 | ✅ 两次启动**复用同一** `state_host-20260926-235952.log` |
| 退出收尾（D4 Job） | ✅ `cleanup ok` |
| 终止码语义 | `code=4294967295`(0xFFFFFFFF) = `Stop-Process -Force` 的终止码，符合预期 |

**仍属未验**：退避**封顶/重置**路径（未构造）——`tray` 重启与真实设备 E2E 已在 §7 / §8 补验。

## 10. D8(a)：`host.json` 显式当前用户 ACL（同日实现并验证）

`state_host.cpp` 的 `write_host_descriptor()` 在写出 `host.json` 后调用新增的 `restrict_descriptor_acl()`：取当前进程 token 的用户 SID → `SetEntriesInAclW` 构造**仅含该 SID** 的 DACL → `SetNamedSecurityInfoW(..., DACL_SECURITY_INFORMATION | PROTECTED_DACL_SECURITY_INFORMATION, …)`（`PROTECTED_DACL` 会**剥离继承 ACE**）。ACL 失败**仅告警**、描述符照常写出（不阻断 host 启动）。

构建：`BUILD_OK`；`state_host.exe` **560,640 B**（改前 559,104 B，确证变更生效）。

验证（先删 `host.json`，再运行 8 s 自退，然后 `icacls`）：
```
C:\Users\home\AppData\Local\sticks3\host.json DESKTOP-F7NTBB2\home:(F)
```

| 判据 | 结果 |
| --- | --- |
| 仅当前用户可访问 | ✅ 唯一 ACE = `DESKTOP-F7NTBB2\home:(F)`；**无** `BUILTIN\Users` / `Everyone` / 继承项 |
| 失败不致命 | ✅ 代码路径：ACL 失败仅 `WARN`，描述符仍写出 |

**D8(b)（token 复用 bridge token）仍未实现**——实现注记（含写盘/鉴权时序坑）见 [LLD §5 表 3b](../StickS3_OpenCode_S4.7-启动器LLD草案.md)。

## 11. D8(b)：控制端点 token 复用 bridge token（同日实现并验证）

改动（`state_host.cpp`）：
1. `bearer_ok()` 在比较 `g_host_token` 前加 `std::lock_guard<std::mutex>(g_voice_mu)`——该变量如今可被主循环更新，而 http 线程并发读，必须同步。
2. 主循环取得 bridge token 后：**若未显式设置 `STICKS3_HOST_TOKEN`**，把 `g_host_token` 换成 bridge token 并**重写 `host.json`**（复用 §10 的 ACL 路径），打印 `control token -> bridge token (epoch)`；显式设置该环境变量时**保持旧行为**（可覆盖）。

构建：`BUILD_OK`；`state_host.exe` **561,152 B**（D8(a) 后为 560,640 B）。
