## 2. 信号选型（含实测反证）

### 2.1 权威寄存器语义（M5PM1 数据手册 V1.9 + 官方 `m5stack/M5PM1` 驱动 + M5Unified）

| 信号 | 语义 | 结论 |
| --- | --- | --- |
| `PWR_SRC (0x04)` | **位图**：bit0=5VIN(USB)有效、bit1=5VINOUT、bit2=BAT有效 | ✅ **选作 USB 在位主判据** |
| `VIN (0x24/0x25)` | USB 5V 输入电压，2 字节小端，mV | ✅ 二次确认（>4000mV） |
| `GPIO_IN (0x12)` bit0 | **充电状态**（PM1 GPIO0 ← 充电 IC STAT 脚，低=充电） | ❌ **不能当"USB 在位"**（见 2.2） |
| `IRQ_STATUS2 (0x41)` | bit0 5VIN 插入 / bit1 移除（写 0 清） | 未采用（需配 GPIO 为 IRQ 脚） |
| `WAKE_SRC (0x05)` bit1 | VIN 插入唤醒 | 未采用 |

补充事实：**PMIC 内没有"USB 在位"专用寄存器**，充电状态来自外部充电 IC 的 STAT 脚；`M5PM1_Class::isCharging()` 在 M5Unified 中是**永久桩函数（返回 false）**，`Power_Class::isCharging()` 才是读 `0x12` bit0。ESP-IDF `usb_serial_jtag_is_connected()` 依据 **SOF 包**判定 → 接充电宝/纯供电会被判"未连接"，**不可用于本策略**。

### 2.2 实测（80s 全寄存器转储，`pm1.c` 临时探针，测毕已删）

插电充电期间：

```
0x04=0x05  0x06=0x17  0x12=0x14  VBAT 0x1008–0x1028 (4104–4136mV，逐升)  VIN 0x13da–0x1414 (5082–5140mV)
```

**充电停充瞬间（尾部）**：

```
0x12=0x15 (bit0=1 → 未充电)   VBAT 骤降至 0x0ff6–0x1000 (4086–4096mV)
0x04=0x05 (不变)              VIN ≈0x140c (5132mV，USB 仍在)
```

对应串口电池行：`battery 4096mV 99% chg=0`（uptime 178938ms），而**此刻 USB 仍插着**。

→ **决定性反证**：`CHG_STAT` 表达的是"**在充电**"，不是"**插着 USB**"。若用它做策略，**插电满电/停充期间会被误判为电池模式而息屏**，违反已批的"USB供电常亮"。

### 2.3 物理限制（诚实登记）

**串口与供电同一根 USB**：拔掉 USB 的同时串口断开（日志中那次 `OPEN 22:59:55` 即拔插所致，期间无输出）。因此 **"纯电池状态"下的寄存器值无法用串口观测**，`0x04` bit0 是否在拔出时清零**只能靠 §5 的行为验证**。

## 5b. 附带交付：录音画面 + 修一处颜色缺陷（用户提出）

用户反馈"按录音键屏幕无变化，无法判断是否在录" → 查得两因并修复：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 按录音键无任何反馈 | ① `REC` 标记只在第 0 页；② **`audio_session.c:58` 要求 BLE 主机已连接且已订阅音频**——未连主机时会话根本不启动（当时日志 `ble_conn=0`，**实际并未录音**） | 新增**全屏录音画面**（三页通用）：`REC` + **计时秒数**（每秒刷新，证明会话存活）；未连主机按住则显示 **`NO HOST`**；`main.c` 按下/松开同步 `display_set_rec_hold()`（commit `856dc00`） |
| `REC` 显示成**蓝色** | `draw_char_px`（像素字号绘制路径）**漏 `pxswap`** → 颜色 G/B 互换：红 `0xF800` 被写为 `0x00F8` 显蓝 | 补 `pxswap(color)`，与 `draw_char8` 一致。**同一缺陷致 `BUSY` 状态词长期错色**，一并修正为设计色 `#3399FF` |

教训（与既有条目同源，已入库）：**新增绘制路径必须与既有路径的色彩约定一致**。此前的教训是"模拟器与固件布局必须一起改"，本次复现为其色彩版本：**模拟器色彩正确，而固件像素字号路径漏了字节交换**。
