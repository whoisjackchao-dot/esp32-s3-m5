# PERF-02 — 20 次意外断线恢复（M5）证据

> 日期：2026-09-27。用例：**PERF-02**（M5）。门槛：**≥19/20 次 ≤15s**。
> 结论：**20/20 次 ≤15s（最差 1.684s）→ PASS**。
> **边界（重要）**：本测量的中心是**测试工具（Bleak）**，非 `state_host`；测的是**设备/链路恢复**（断链→重连→加密→会话健康）。见 §3。

## 1. 环境 / 条件
- 设备 `70:04:1D:D6:21:D2`（StickS3）；固件含 **`0x7F` 测试钩子**（设备主动断链）。
- 位置：**同一工位 ~0.3–2m、无遮挡（待用户确认）**；无线共存＝当前办公室环境（未专项记录）。
- 中心：`tools/perf02_reconnect.py`（Bleak）；用**已有 bond**、**不重新配对**（仅首连尝试 `pair` 一次）。
- 为释放设备，本次**停掉了 launcher/tray/state_host**（见 §3 边界）。

## 2. 结果（2026-09-27）
- 机制：连接+订阅+`READY→BEGIN` 健康后，写 `0x7F` 令**设备主动断链**；`t0`=断链时刻，`t1`=恢复"加密连接+会话健康"；Δ=t1−t0。
- **20/20 次 Δ ≤ 15s**；Δ 范围 **0.549–1.684s**；**最差 1.684s**。`VERDICT=PASS`。
- 逐条 Δ(s)：1.090, 1.576, 1.035, 0.802, 1.577, 0.614, 0.622, 0.673, 1.397, 0.556, 0.549, 1.447, 1.146, 0.668, 0.609, 1.636, 0.557, 1.684, 0.677, 0.677。

## 3. 边界（不得省略）
- **中心＝测试工具**：本测**未**验证 `state_host`（产品常驻中心）自身的重连循环；测的是**设备/链路**的恢复。→ **产品侧（state_host）重连 + STATE 复原仍需另行验证**（§4）。
- **"加密"** 为近似：用已有 bond 连接（Windows 缓存）；Bleak 不直接暴露加密位。
- **"同步状态"** 近似为"会话健康（`READY→BEGIN`）"，**非** host 的 `STATE(0x12)` 推送。
- **Harness 说明**：首轮 20 次中有 10 次是**setup 连接**（Windows BLE 栈沉降不足）假失败；已加长迭代间沉降 + 失败重扫修正。**setup 失败不计入被测恢复**（第二轮 20/20 全部为有效恢复测量）。
- 关机 / 蓝牙关闭的等待未含（PERF-02 要求单列）。

## 4. 待办
- 若需**产品侧** PERF-02：给 `state_host` 加受限断链测试模式（或物理断电 20 次），测**host 重连 + STATE 复原**。
- 用户确认设备位置（0.3–2m、无遮挡）与无线共存条件。
